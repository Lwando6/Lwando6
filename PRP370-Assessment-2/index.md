## Portfolio approach

The assessment brief requires four e-portfolio activities:

1. **Collect** — gather and organise artefacts from the project.
2. **Select** — choose relevant artefacts that demonstrate learning and development.
3. **Reflect** — explain what the evidence demonstrates and what was learned.
4. **Connect** — show relationships across the artefacts and reflections.

## Evidence integrity and limitations

This is an individual assessment. The portfolio describes my own project work and uses repository history as dated implementation evidence.

The available Git history does not by itself prove formal sprint planning, Trello activity, daily stand-ups, user interviews, task estimates, testing outcomes or retrospective meetings. These are not invented here. Where original records are not yet available, the portfolio identifies information that must be added or verified.

Reflection sections include drafts and prompts. They must be reviewed and personalised so they accurately represent my own decisions, challenges and learning before submission.
